<h2 align="center">trizy 0.3.0: the first public release</h2>

<p align="center"><b>One operating contract for every coding agent in your repository.</b><br>
Plan, build, review, gate and journal: enforced by git hooks, written in POSIX sh, nothing to install but git.</p>

---

Agents are good at writing code but bad at discipline. They skip the review, claim a test passed without running
it, over-build, and repeat a mistake someone corrected yesterday. trizy puts the rules in the repository and lets
git hooks enforce them, for Claude Code, Codex and the people working next to them.

### Highlights

| | |
|---|---|
| 📜 **A contract in the repository** | `AGENTS.trizy.md`, four rule files and a `CONSTRAINTS.md` that collects every correction, imported into `CLAUDE.md` and `AGENTS.md` |
| 🚦 **Gates that refuse** | pre-commit requires an approved review receipt for exactly the staged tree (the reviewer is not the author); pre-push requires a journal entry newer than the pushed commits |
| 📐 **Optimality per decision** | every new file, store, mechanism or format names the cheaper options and the constraint that rules each one out |
| 🧭 **Flows and steps** | `commit`, `push` and your own flows in `.trizy/flows.tsv`: shell `run` steps and `ask` instructions |
| 🧪 **The `deliver` pipeline** | a task becomes a plan the owner approves, then packages, each built in its own worktree and passed through an independent gate |
| 🗂 **A memory of runs** | a local journal shared by worktrees; the weekly `retro` skill reads it and proposes changes to the rules |
| 🪝 **Plays well with husky** | `init` offers to replace a foreign hooks path (recommended) or merge with it |

### How a package moves

```text
task ──▶ plan ──────────▶ build ─────────▶ gate ─────────────────▶ merge ──────────▶ verify
         owner approves   own worktree     independent review      deliver/<slug>    + journal
                            ▲                │
                            └── findings ────┘  (up to 3 attempts, then the package is reported failed)
```

### Quick start

```sh
curl -fsSL https://raw.githubusercontent.com/ts-ign0re/trizy/main/install.sh | sh
cd your-repo
trizy init                                  # agent files in git (team-wide) or ignored (local)?
trizy step add commit lint run "make lint"  # what the pre-commit gate runs
trizy step add push test run "make test"    # what the pre-push gate runs
trizy check
```

| Gate | Refuses |
|---|---|
| pre-commit | a failing `commit` step; a commit without an approved receipt for exactly the staged tree |
| pre-push | a pushed commit that is not this clean checkout's HEAD; commits with no journal entry after them; a failing `push` step |

### What's inside

- **Skills:** `optimality-check`, `review-gate`, `retro`, plus `ponytail`, `ponytail-review` and
  `security-reviewer` (MIT, see [THIRD-PARTY-NOTICES.md](https://github.com/ts-ign0re/trizy/blob/v0.3.0/THIRD-PARTY-NOTICES.md)).
- **Tools:** `trizy worktree` (always from the freshly fetched main branch), `trizy heavy` (a machine-wide queue
  for heavy commands), `trizy review`, `trizy log`.
- **Track or ignore:** commit the agent files for the whole team, or keep them local to your clone.
- **Pinned per repository:** every project runs its own copy, so teammates without the install still have
  working hooks.
- **Releases by tags:** `install.sh` installs the latest release and verifies its SHA-256; `trizy upgrade
  [--version vX.Y.Z]` does the same for an existing install.

### Coming from agent-kit

trizy used to be agent-kit, which was never published. The command, directory, markers and variables are now
`trizy`, `.trizy/`, `trizy:begin` and `TRIZY_*`. Remove `.agent-kit/` and its blocks in `CLAUDE.md` and
`AGENTS.md` (and the agent-kit lines in merged hooks), then run
`trizy init --hooks=replace` (`core.hooksPath` still points at `.agent-kit/hooks`).
